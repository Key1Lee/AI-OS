# Testing and test evidence

Testing is a mechanism used during Implementation and independent [Verify](verification.md). An explicit `/test` request asks a tool-capable agent to select or create relevant checks, run them, and report reproducible evidence; it is native agent behavior under `AGENTS.md`, not a new Skill, CLI command, framework, or mandatory lifecycle stage. The shared `py_dev` Skill runner has no repository tool executor, so a model response cannot substitute for a recorded test run.

## Repository test surfaces

Use the affected project's instructions and existing deterministic tooling. The shared layer uses `python3 -m unittest discover -s tests -q`; Skill mirrors use `python3 scripts/sync_skills.py --check`, and AI-OS conformance uses `python3 skills/audit/scripts/check.py --live` when relevant. [Northstar's project guidance](../projects/Northstar/AGENTS.md) names its offline workflow and contract checks; its [regression baseline](../projects/Northstar/northstar-leadops/docs/regression-baseline.md) adds a baseline runner and states what offline checks cannot prove. [Toptal's project guidance](../projects/Toptal-Testing/AGENTS.md) requires relevant checks and preserved expectations; its [README](../projects/Toptal-Testing/README.md) gives `pytest` and launcher syntax commands. No repository-wide CI, pre-commit hook, type-check gate, or shared test-selection utility was found at this inspection. Project checks remain project-owned.

## Selection and evidence

Start with the changed behavior and directly affected test. Expand to its module or package, integration boundary, then broader suite only when changed contracts, shared interfaces, persistent data, security, concurrency, or observed failures justify it. Implementation may run fast targeted checks as development feedback without a separate Test invocation. Add a durable test when new observable behavior, a confirmed regression, or a material boundary lacks protection. Test contracts and behavior, not implementation shape. Preserve valid expectations; require contract or fixture evidence before changing an existing test to match a new result.

For each relevant check, report behavior and scope exercised, exact command and test IDs when useful, **passed**, **failed**, or **not executed**, concise output or failure evidence, new coverage, relevant skipped checks, and blockers or credible pre-existing failures. Keep raw logs available for diagnosis rather than pasting them wholesale. A passing test supports only the behavior it actually exercises. Test produces evidence; Verify maps the total evidence to every approved criterion and makes the acceptance decision.

If a focused test reveals an obvious implementation defect, hand its reproduction to Implementation. If causality is unclear, preserve the failure and route to [Debug](debug.md). Separate a dated baseline-supported pre-existing failure from a new regression. An unavailable service, fixture, credential, or test environment means **not executed reliably**, not a product test failure. For inconsistent results, report run conditions and frequency; do not declare flakiness or correctness from one result. After a correction, run the relevant regression check and return evidence to Verify. Review and Audit retain their distinct scopes.

## Evaluation and limits

`evals/test-cases.toml` contains ten positive and eight negative routing fixtures. In a local Qwen label-only trial, a basic workflow prompt routed 13/18 correctly; a short Test boundary instruction routed 17/18. Both still mistook a quick check during Implementation for a separate Test task. In six further stipulated situations, the short instruction correctly treated an unavailable database test as not executed and sent an obvious failed assertion to Implementation; the basic prompt misclassified both. Scope labels were still inconsistent. These prompt trials do not execute tests or qualify model-only testing. The direct repository commands above provide the deterministic evidence; Codex and Claude were not separately benchmarked, and optional cloud adapters were not called. A dedicated Test Skill would duplicate the same guidance without adding tool execution.
