# Product contract

Default journey: dashboard → Continue Training → one problem → editable SQL →
Run visible fixture → Submit hidden cases → evidence-based result → progress →
recommended transfer exercise. Existing active drafts resume before selection.

Practice offers filters and progressive hints. Strict SQL interview practice
offers explicit clarification, assumption notes and optional timing; no automatic
hint. The full mixed interview and take-home modes follow the roadmap. Navigation
must identify unavailable modes honestly rather than presenting fake interaction.

Dashboard, library, competency evidence, mistakes, review queue and history are
real database views. Empty history is shown as unassessed, never invented scores.
SQL correctness comes exclusively from execution. Explanations are stored but
not scored by keyword heuristics. Reasoning evaluation requires a configured,
validated provider in its future integration.

Draft changes autosave and can be explicitly saved. Run does not complete an
attempt or award mastery. Submit freezes that attempt. Revising creates a new
linked attempt with prior assistance/solution exposure preserved. Solutions are
available after completion or explicit reveal; revealing an active solution
marks exposure before returning it. Errors preserve text.
