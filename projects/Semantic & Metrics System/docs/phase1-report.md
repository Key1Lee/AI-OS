# Phase 1 completion report — maintainer evidence

This report reveals the training incident outcome. It describes implemented behavior and distinguishes local fixture proof from production readiness or learner mastery.

1. **Actual semantic architecture:** stdlib JSON registry → validated owner/grain/time/version contract → bounded already-modeled snapshot evaluator → governed dashboard/API/SQL/AI results. CLI, learning state and five artifact exports remain project-owned.
2. **Existing definitions discovered:** seven entries in the inventory cover Modeling gross completed revenue, Quality net reconciliation, dbt completed amount, AE gross revenue, Observability's deliberate fanout demo, FDE FIN-NET-1 UTC net and Growth booked gross. Existing meanings were preserved.
3. **Entities created:** Order/order_id, Customer/customer_id and Product/product_id, each with source, grain, owner, relationships and identity policy. Payment/Refund entity expansion is deferred; refunds are a modeled Order-level measure input.
4. **Dimensions created:** date, channel, region, product_category. Current snapshot behavior and N:1 relations are explicit. Category is unsupported for active_customers in the bundled contract.
5. **Measures created:** gross_order_value, refund_amount and order_count, bound to explicit Order-grain modeled assets and integer cents/counts.
6. **Metrics created:** gross_revenue, net_revenue, orders and active_customers. Fixture window 2026-09-30 inclusive through 2026-10-02 exclusive yields gross $8,700,000.00, net $8,200,000.00, 2 orders and 2 distinct canonical purchasing customers.
7. **Metric ownership:** accountable Finance (synthetic) and technical Semantic Platform (synthetic) are separately recorded. Owner approval covers business prose and executable meaning; it never claims real customer approval.
8. **Time semantics:** fulfilled_at, America/Chicago, Gregorian dates, fulfilled USD population and refund restatement to the Order reporting date through snapshot as_of. The event 2026-10-01T01:00Z belongs to Sep30 locally. Existing sibling UTC contracts remain independent.
9. **Lineage:** raw source → staging → fact/dimension → measure → gross/net dependency → five consumers. Missing dependencies, incompatible definitions/grain/time, duplicate metric versions and cycles fail validation.
10. **Tests executed:** `python3 -m semantic validate`, `python3 -m unittest discover -s tests -v`, CLI query/opening probes. See [check-results.md](check-results.md) for counts and coverage. These are implementation evidence; independent helper inspection is a separate acceptance check.
11. **SEM-REVENUE-001 result:** reproducible authored opening $8.7M versus $8.2M with technical PASS reports. Requested evidence reveals gross versus net, then owner policy. A learner proposal matching that owner decision is governed in scenario-local state; Dashboard A/B, API, AI and SQL produce the same $8.2M with the same definition/source provenance. Four regression guards prevent formula overrides, fanout, owner omission and time drift. Recall is still unassessed.
12. **Modeling integration:** executed modeled-snapshot input validation and an explicit export fixture. Modeling retains transformation, refund preaggregation and identity mapping; live SDK integration is deferred.
13. **Quality integration:** semantic check-requirements artifact, without a duplicate quality engine. The incident technical PASS statuses are authored evidence, not native checks executed by this project.
14. **Observability integration:** coherent `data-map-v1` metadata export with declared lineage and UNKNOWN operational status. Live ingestion and measured health remain outside this slice.
15. **AE Lab integration:** exported scenario reference and entry point. AE owns its existing run/learning state; no native AE adapter is installed.
16. **FDE Lab integration:** explicit discovery-handoff artifact with required decision/owner/time/grain fields. The synthetic new Finance contract does not overwrite Northstar FIN-NET-1.
17. **AI consumption:** an `ai` consumer sends a versioned structured request to the same evaluator. No LLM call is needed or claimed; caller-created formulas and SQL are rejected.
18. **Known gaps:** no live sibling connections, warehouse SQL execution, BI deployment, authenticated owner approval, production access policy, fiscal calendar, SCD history, identity resolver, multiple-product allocation, advanced metric composition or transfer scenario. Human understanding and free-text reasoning require tutor assessment. Bundled schema JSON validates structure; executable cross-field semantics live in Registry. Operating on modified source artifacts relies on local repository trust; fingerprints provide traceability, not cryptographic authorization.
19. **Exactly one next improvement:** add the owner-driven `SEM-TIME-001` transfer scenario, using the same evidence gates and an explicitly different recognition-date decision to test understanding beyond the first fixture.
20. **Three recall questions:** Why can technically healthy dashboards disagree? What does one row represent, and how can a join change it? Which owner, identity, event-time, timezone and version rules must an AI result preserve? Answers are intentionally absent.

The learner-understanding criterion remains **unproven** until the user answers recall and an independent tutor assesses it. The software cannot certify that the user can explain the system simply because deterministic code checks pass.
